# 鸿蒙 PC 适配计划

## 当前状态

当前代码是 Qt 6 桌面原型。尚未提供可安装 HAP、鸿蒙 QPA 插件或可执行的设备侧沙箱服务，不应将 Windows 运行截图当作鸿蒙运行证据。OpenHarmony 与商业 HarmonyOS 的 SDK、分发规则和接口可能不同，须按实际目标系统核实。

## 接入步骤

1. **确定平台组合**：目标设备型号、系统/API 版本、CPU ABI、Qt 版本、现有 Qt for OHOS 发行版或平台插件来源。先让最小 Widgets 窗口在设备上运行，验证字体、输入法、缩放、键鼠及剪贴板。
2. **交叉编译**：使用实际 SDK 的 CMake toolchain 和为同一 ABI 构建的 Qt。不要将 Windows/Linux Qt 库复制到设备。`CMAKE_PREFIX_PATH` 指向目标 Qt；宿主 moc/rcc 工具按该 Qt 发行版文档配置。
3. **文件访问**：将桌面 QFileDialog 映射到系统允许的文件选择/授权机制。将用户选中的工程复制到应用私有可写目录，保存时显式写回获得授权的位置；处理目录授权、URI 与路径的差别。
4. **执行服务**：替换 `picocCommand(OhosSandbox, ...)` 的拒绝分支，接入独立受限执行服务。不要直接在 UI 进程解释用户代码。若目标系统禁止 QProcess/fork/exec，应通过平台 IPC 服务提供运行，而非绕过平台限制。
5. **工程互通**：导入项目时规范化分隔符和路径大小写；提示缺失绝对路径。导出原始 .cbp 和源文件，保留未知 XML 配置。
6. **打包与验收**：按 Qt 平台发行版提供的方式生成项目包、签名并部署到真实 PC 设备，完成下面的验证清单。

## 建议的执行服务契约（尚未实现）

请求包含：runId、UTF-8 单文件 C 源码、stdin 通道、wallTimeMs（≤10,000）、outputLimitBytes（≤1,048,576）。服务自行限制源码大小，不接受宿主任意绝对路径或 shell 命令。

响应事件：started、stdout、stderr、exit（code/reason）、error；停止请求携带 runId。输出传输需背压，退出事件只产生一次。停止、超时、UI 断连应清理本次任务的整个进程/执行实例及临时文件。

服务要求：独立执行实例、仅任务目录可写、应用私有数据不可读、默认无网络、限制宿主函数/系统调用、限制内存/CPU/进程数量、可信 picoc 二进制、崩溃恢复。具体可用 API 必须依据目标 SDK 文档验证。

picoc 自身不是安全边界。桌面 QTemporaryDir + QProcess 超时也不是安全沙箱。当前 Linux bubblewrap 路径只是桌面隔离原型，不能代替鸿蒙应用沙箱或服务侧权限隔离。

## 真机验收清单

- 启动、窗口缩放、多显示器、触控板/键鼠、中文输入法与字体。
- 打开/保存授权目录，重启后授权行为、导入和导出包含中文与空格的工程。
- C/C++ 语法高亮、未保存提示、只读文件、外部修改与异常退出恢复策略。
- .cbp 从桌面导入 → 修改 → 导出 → Code::Blocks 再打开，未知节点无损。
- picoc 的正常退出、编译/解释错误、stdin、死循环、无限输出、大量内存、崩溃、取消、应用退后台。
- 禁止访问宿主文件/网络/其他任务，检查后代进程清理；服务未就绪时不回退到无隔离执行。

验收结果应记录设备、系统、Qt/SDK/picoc 版本、构建方式、复现步骤和日志。
